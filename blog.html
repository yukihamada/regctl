— 1コマンドでRaspberry PiをAIカメラに

2026年2月27日 · ミセバンAI チーム · 約3分で読めます

regctl.sh チームが開発するもう一つのプロダクト、ミセバンAI（防犯カメラをAI来客分析カメラに変えるSaaS）のカメラエージェント v1.0.0 を本日正式リリースしました。

ミセバンAIの最大の課題は「Raspberry PiにエージェントをインストールするのがITに不慣れな店舗オーナーには難しすぎる」こと。解決策はシンプルだった：1コマンドで全部終わらせる。

Terminal — Raspberry Pi
$ curl -fsSL https://misebanai.com/install.sh | bash

このコマンドひとつで：バイナリダウンロード、ffmpegインストール、systemdサービス登録、セットアップウィザード起動まで自動完了。完了後にブラウザでURLを開けばカメラが自動検出されてすぐ使えます。

Engineering Product Design

regctl.sh をワールドクラスにした方法
— マルチエージェント・エンジニアリング会議

2026年2月26日 · regctl.sh チーム · 約10分で読めます

先週、変わったプロダクトレビューをした。会議室ではなくSlackチャンネルが舞台で、人間の同僚ではなく3つの専門AIエージェント — CTO、マーケティングリード、デザイナー — がそれぞれ regctl.sh の異なる側面を自律的に監査した。この記事は、彼らが何を発見し、何を実装し、そして「ひとりで作ったソフトウェアを監査するうえでマルチエージェントエンジニアリングがなぜ最も効果的か」という話だ。

🏗 問題：ファウンダーのブラインドスポット

regctl.sh はもともと個人用のCLIツールだった。1コマンドで全レジストラのドメイン価格を一括比較する、それだけ。でも数ヶ月で成長した — 897 TLDが1,343になり、Value Domain対応は5社比較エンジンになり、単純なJSONファイルが認証・課金・DNS管理・ドメインマーケットプレイス・AI生成サイトを備えたフルスタックWebアプリになった。

ただ、ソロ開発者には有名なブラインドスポットがある：自分の思い込みは自分では見えない。すべてのトレードオフを自分で決めたから、なぜそうなっているかは知っている。でも摩擦に気づかない、なぜなら無意識に回避しているから。最初のデプロイ以降、セキュリティヘッダーを確認すらしていない。

解決策はラジカルだった：3つのAIエージェントを並列で起動し、それぞれ異なる役職を与え、独立してコードベースを監査させる。

🔵 CTOレポート：田中 Ryo

セキュリティヘッダー — ギャップ分析

Ryo が最初に発見したのはセキュリティヘッダーのセットだった。X-Content-Type-Options と X-Frame-Options は存在していたが、重要なヘッダーが3つ抜けていた：

// server.go — ServeHTTP() + w.Header().Set("Strict-Transport-Security", "max-age=31536000; includeSubDomains") + w.Header().Set("Referrer-Policy", "strict-origin-when-cross-origin") + w.Header().Set("Permissions-Policy", "camera=(), microphone=(), geolocation=()")

HSTSは、ユーザーが手動で http:// と入力しても以降は必ずHTTPSを使うことを保証する。Referrer-Policyは、外部リンクをクリックした際に Referer ヘッダーを通じてauthトークンが漏れるのを防ぐ。Permissions-Policyは使っていないブラウザAPIを明示的に無効化し、フィンガープリンティングを防ぐ。

BulkCheck — レート制限ゼロ

CT
田中 Ryo
POST /v1/domains/check はレート制限なしで1リクエスト最大50ドメインを受け付けます。攻撃者は27リクエストで全1,343 TLDを叩けます。このままだとレジストラAPIからBANされるか想定外のコストが発生します。IPベースのスライディングウィンドウかリクエストキャップが必要です。

これは次スプリントのロードマップに追加した。修正方法は、IP + APIキーをキーとするスライディングウィンドウのレート制限をミドルウェア層に追加すること。

構造化データ — JSON-LD が完全に欠落

元の <head> にはSchema.orgのマークアップが一切なかった。これではGoogleがリッチリザルト（サイトリンク検索ボックス、アプリカード、パンくずリスト）を表示できない。WebApplication + WebSite + SearchAction の完全なグラフを実装した：

{
  "@context": "https://schema.org",
  "@graph": [
    {
      "@type": "WebApplication",
      "name": "regctl.sh",
      "applicationCategory": "UtilitiesApplication"
    },
    {
      "@type": "WebSite",
      "potentialAction": {
        "@type": "SearchAction",
        "target": "https://regctl.sh/{search_term_string}"
      }
    }
  ]
}

SearchAction により Google のサイトリンク検索ボックスが有効になる — ユーザーはGoogle検索結果ページから直接regctl.shを検索でき、クリックせずに済む。

🟢 マーケティングレポート：佐藤 Mika

OGP + Twitterカード — 両方とも未設定

MK
佐藤 Mika
致命的なギャップ：og:image も twitter:card タグも存在しません。Twitter/Slack/Discordでシェアするたびにプレーンテキストリンクになってます — プレビュー画像もカードも出ない。タダで手に入る配信を捨ててる状態です。しかもog-image.svgは既にstaticディレクトリにある！

アセットは既に存在していたのに参照していなかった、という恥ずかしいやつ。4行のHTMLで修正した：

+ <meta property="og:image" content="https://regctl.sh/og-image.svg"> + <meta name="twitter:card" content="summary_large_image"> + <meta name="twitter:title" content="regctl.sh — 世界最安値のドメイン登録"> + <meta name="twitter:image" content="https://regctl.sh/og-image.svg">

SEO向けH1スタティックフォールバック

Mikaはヒーローの見出しがJavaScriptで注入されていることを指摘した。GoogleのクローラーはJavaScriptをインデックスするが、2パスのプロセスだ — 最初のパスは純粋なHTMLで、2パス目がレンダリングされる。レンダリングに遅延があれば、H1がインデックスされない可能性がある。修正：<noscript> 静的H1を追加し、DOMの最初のH1がJS実行後ではなく初期HTMLに存在するようにする。

バイラルメカニクス：スラッグルート

「あなたが持っている最もバイラルな機能はすでにライブだが、誰も知らない。regctl.sh/startup にアクセスするだけで startup.com、startup.io、startup.dev の価格が一発で分かる。これはツールチップの小さなテキストに埋もれてる場合じゃなく、ヒーローコピーのメインにすべきです。」
— Mika、マーケティング監査

このインサイトがヒーローセクションの書き方を変えた。「regctl.sh/あなたの名前 を打ってみて」が、小さな注釈ではなく一番目立つ主要CTA訴求として前面に出た。

🟠 デザイナーレポート：Chen Kai

コントラスト違反：--muted2

CK
Chen Kai
WCAG AA違反を発見。--muted2:#555 on --bg:#111 のコントラストは3.0:1。AAは通常テキストで4.5:1、大きいテキストで3:1が必要です。サイドバーラベル、inputプレースホルダー、フォームヘルパーが全部 --muted2 を使っている — 全部アウト。#6b6b6b なら3.8:1でAA（大テキスト）クリア。#777 は4.5:1で完全準拠。

アクセシビリティは「あるといいもの」ではなく、多くの法域で法的要件であり、視覚障害のあるユーザー・明るい日光下・低輝度ディスプレイでの実用性に直接影響する。実装：

- --muted:#888;--muted2:#555; + --muted:#9a9a9a;--muted2:#6b6b6b;

アクティブステートの欠如

すべてのボタンに :hover はあったが :active がなかった。モバイル（タッチスクリーン）ではhoverは存在しない — タップした瞬間の唯一のフィードバックがアクティブステートだ。これがないとタップが「反応しない」と感じられる。

+ .btn:active { transform: translateY(0)!important; box-shadow: none!important; opacity: .85; } + .btn-primary:hover { transform: translateY(-1px); box-shadow: 0 4px 12px rgba(246,130,31,.35); }

hoverで浮き上がり、activeで押し込まれるスナップバックが、iOS/Androidのネイティブボタンの押し心地を再現する。

タイポグラフィスケール：font-sizeが15種類

CK
Chen Kai
CSSのfont-size値を数えると…15種類あります。よく設計されたシステムは5〜7ステップ。アドホックに選ばれたサイズはタイポグラフィスケールではなく、その場の直感です。推奨：.72 / .78 / .85 / .92 / 1rem / 1.1 / 1.4 / 2.2rem — 8ステップ、全ユースケースをカバー。このスケール外は設計判断ではなくtypo（ミス）と見なす。

これは次のデザインスプリントでリファクタリング予定。最初のステップはすべての font-size 宣言を洗い出し、タイプスケールの最近接ステップにマッピングすること。

🤖 マルチエージェント監査がうまくいく理由

このプロセスで興味深かったのは、個々の発見ではなかった — 経験豊富なエンジニアなら通常のコードレビューで同じことを見つけるだろう。際立っていたのは並列性だ。

通常のコードレビューは逐次的だ：一人に聞く、一つの視点が返ってくる、修正する、また聞く。マルチエージェント監査は並行的だ：3つの専門的な視点が同時に同じコードベースを、異なる角度から、コンテキスト汚染なしに見る。

MikaはRyoがセキュリティヘッダーを見ていることを知らなかった。KaiはMikaがOGPを見ていることを知らなかった。各エージェントはコードベースをフレッシュな状態で、自分の専門領域から、他のエージェントの発見にアンカリングされることなくアプローチした。これが本物のハイパフォーマンスチームの動き方だ — 並列特化、そして統合。

「最高のチームは頭が良いのではなく、並列化が上手い。」

このセッションは、個別の修正リスト以上に価値あるものを生んだ：プロジェクトの品質基準を表す共通言語。Kaiが「font-sizeが15種類というのは、15個の下されなかったデザイン判断だ」と言ったとき、それは今後すべてのフィーチャーに適用するヒューリスティックになった：アドホックな選択ではなく、明示的なデザイン判断。

🚀 今後のロードマップ

監査から生まれたロードマップ：

  • BulkCheckのレート制限 — IP + APIキーをキーとするスライディングウィンドウ
  • prices.json のETagキャッシュ — 帯域削減、CDNエッジキャッシュの有効化
  • スラッグページの動的OGP — regctl.sh/startup がライブ価格つき専用og:imageを持つ
  • タイポグラフィシステム — 8ステップ型スケール、CSSカスタムプロパティで強制
  • ソーシャルプルーフセクション — DBから取得した「登録済みX件・ユーザーY人」
  • IntersectionObserver スタガーアニメーション — スクロール連動のフィーチャーカード演出

regctl.sh のミッションはシンプルだ：ドメイン登録をとことん安く・簡単にして、価格を理由にアイデアを諦める必要をなくす。マルチエージェント監査は、「動く」と「ワールドクラス」の間のギャップを体系的に埋め続けるための方法のひとつだ。
